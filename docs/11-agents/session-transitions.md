# Переключение агентов в середине работы

В отличие от handoff-протокола (который про передачу законченного PR), эта страница — про **переключение агента посреди задачи**: когда тикет ещё не закрыт, но удобнее продолжить другим агентом.

## Когда переключаться

Сигналы:

1. **Природа задачи сменилась.** Начинали как архитектурный риск (Claude Code), стало понятно, что осталась механическая часть → Codex.
2. **Появилась UI-часть.** Backend готов, осталась полировка интерфейса → Cursor.
3. **Зашёл в тупик.** Сессия топчется на одном и том же — закрыть, новый агент свежим взглядом.
4. **Длинный fixup.** Codex эффективнее на массовых правках; Claude Code лучше на дискуссиях.
5. **Закончились ресурсы текущего агента.** Можно «доехать» другим.

## Безопасное переключение: чек-лист

1. **Сохранить текущее состояние**.
   Если есть git-checkout:
   ```bash
   git add -A && git commit -m "wip(<area>): mid-task handoff"
   ```
   Если текущая server working copy без `.git`:
   - создать/обновить handoff-файл в `docs/11-agents/`, либо
   - зафиксировать handoff в `milestones.md` и комментарии к тикету.
2. **Открыть тикет в milestones.md** (если ещё не открыт).
3. **Записать промежуточный handoff** в комментарии тикета (см. [handoff-protocol.md](handoff-protocol.md), секция «Шаблон коммита»).
4. **Закрыть текущую сессию.**
5. **Открыть нужного агента, прочитать handoff.**
6. **Подтвердить понимание.** Перед началом работы новый агент пишет в чат (или в комментарий тикета) one-liner «принял».

## Что обязательно зафиксировать в WIP-коммите

- Список «открытых дверей» (что не доделано).
- Принятые промежуточные предположения.
- Где у тебя сомнения и нужно ревью человека.

## Anti-patterns

- **«Я просто закрыл сессию, агент в следующий раз разберётся».** Нет, не разберётся. Нет handoff'а — нет восстановления.
- **«Доделаю в другой раз, тикет потом обновлю».** Завтра ты забудешь. Записать СЕЙЧАС.
- **«Cursor допишет, что Claude Code не успел».** Только если есть handoff с конкретикой. «Допиши» — не указание.

## Спецсценарии

### Параллельная работа двух агентов

Иногда полезно держать два агента одновременно:

- Claude Code обсуждает архитектуру изменения,
- Codex параллельно гонит тесты на смежных сервисах.

В этом случае:
- Если есть git — каждый агент работает в своей feature-ветке.
- Если git нет — развести зоны ответственности по файлам и зафиксировать handoff письменно.
- Координация через `milestones.md` и handoff/PR-комментарии.

### Перехват в случае сбоя

Если агент завис / прервался:

1. Owner закрывает зависшую сессию.
2. Открывает любого другого агента.
3. Новый агент читает последний коммит + последний handoff.
4. Если handoff'а нет — Owner кратко описывает в одно сообщение, что нужно. Это и становится handoff'ом.
5. Продолжаем.

### Передача между Claude Code и Cursor через MCP

Cursor (и Claude Code) умеют ходить в собственный MCP PIL (когда он реализован). Полезный кейс:

- Claude Code накатил backend, опубликовал тестовые данные через PIL MCP.
- Cursor стартует с UI, вызывает MCP `get_person_context` напрямую для real-data-проверки.

Так можно поддерживать живой dev-loop без полного e2e.

## Метрика «здоровой» передачи

- Через 5 минут чтения handoff'а новый агент пишет осмысленный план «что сделаю в следующих 30 минутах».

Если так — handoff удался. Если нет — handoff надо доработать.
