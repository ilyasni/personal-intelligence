# Handoff protocol

Как передавать работу между сессиями (одного и того же агента) и между разными агентами без потери контекста.

Это **обязательный артефакт** в каждом PR, WIP-коммите или значимом тикете. Если работа ведётся в server-side working copy без `.git`, handoff живёт в отдельном `.md` файле или в комментарии к тикету/roadmap.

## Шаблон handoff-блока

В описании PR, WIP-коммита, handoff-файле или комментарии тикета добавляй секцию:

```markdown
## Handoff

- **Сделано.** Краткий список (3–7 пунктов) того, что в этом PR/сессии завершено.
- **Не сделано.** Что было запланировано, но осталось за рамками.
- **Принятые предположения.** Что я допустил без подтверждения.
- **Известные риски.** Что может сломаться. Где скрытые мины.
- **Следующий шаг.** Что нужно сделать дальше.
- **Рекомендованный агент.** `claude` / `codex` / `cursor` / `any` — кому удобнее подхватить.
- **Контекст для следующего агента.** 1–3 предложения: ключевые файлы, на что обратить внимание, как тестировать.
```

Пример:

```markdown
## Handoff

- **Сделано.**
  - `services/entity-extractor` — rule-based NER на spaCy, поддержка RU+EN.
  - Контракт `processing.entity_found` в libs/contracts.
  - Integration test против testcontainers Postgres + Redis.
- **Не сделано.**
  - LLM-pass (hybrid) — отложено на MVP-2 D-01.
  - Topic extraction пока только tf-idf, без LLM-валидации.
- **Принятые предположения.**
  - Confidence порог 0.6 для rule-based — взято с потолка. Сменим после калибровки.
  - Reconciliation persons делает простой Левенштейн ≥ 0.85. Не учитывает транслит RU↔EN.
- **Известные риски.**
  - На длинных сообщениях (> 1000 знаков) spaCy медленный; есть batch_size=16, но не профилировано.
  - DLQ при ошибке spaCy теста на edge-cases ещё не покрыт.
- **Следующий шаг.**
  - D-02 persona-builder, использовать entities из этого PR.
- **Рекомендованный агент.** `claude` — задача сквозная: persona-builder зависит от entity-extractor.
- **Контекст для следующего агента.** Смотреть `services/entity-extractor/src/entity_extractor/domain/`, особенно `reconcile.py`. Тест-фикстуры в `tests/fixtures/messages_for_entities.json`.
```

## Где обязателен handoff

- Каждый merge / релизный срез в `main` или его эквивалент.
- Каждый тикет, переведённый в статус «REVIEW» или «PAUSED».
- В конце длинной сессии (если работа не завершена) — комментарий в тикете с handoff'ом.

## Минимум handoff'а (если короткий PR)

Допустимо опустить «Принятые предположения» и «Известные риски», если PR < 50 строк и совсем тривиальный. Остальные пункты — обязательны.

## Forward / backward handoff

- **Forward handoff.** Ты заканчиваешь свою работу и передаёшь следующему — заполняешь блок выше.
- **Backward handoff.** Ты принял чужой блок — НИЧЕГО НЕ ПЕРЕИГРЫВАЙ молча: если не согласен с принятым предположением, открой новый PR с пометкой «revert/refine» и зафиксируй причину.

## Что НЕ нужно делать

- Не дублировать содержимое PR-диффа. Handoff — это «что думаю», не «что сделал на уровне строк».
- Не писать «всё ок, продолжайте». Это нерабочий handoff.
- Не указывать конкретного человека («передаю Игорю»). Указывай агента.

## Связь с milestones.md

- При закрытии тикета — обновляй статус в `docs/09-roadmap/milestones.md` (Owner / status / артефакт).
- Если по ходу появился open question — добавляй в секцию «Открытые вопросы».

## Связь с ADR

- Если по ходу работы пришлось принять архитектурное решение — фиксируй ADR (см. [ADR-0001](../10-adr/0001-record-architecture-decisions.md)).
- В handoff'е — ссылка на ADR.

## Шаблон коммита или handoff-файла (когда сессия закрывается без PR)

Если ты не открываешь PR, но хочешь сохранить состояние:

```bash
git commit -m "wip(<area>): <короткое описание>

Handoff:
- Сделано: ...
- Не сделано: ...
- Следующий шаг: ...
- Рекомендованный агент: codex
"
```

Если `.git` недоступен, положи тот же блок в `docs/11-agents/handoff-YYYY-MM-DD-<ticket>.md`.

Это поможет любому другому агенту восстановить контекст.

## Пример «двойного» handoff'а (агент → агент)

PR от Claude Code → принимает Cursor:

> Claude Code в handoff'е: «Backend готов, осталось добавить страницу `/persons/:id/graph` в UI. Контракт endpoint'а — `GET /v1/graph/walk?start=:id&hops=1`. См. `apps/admin-ui/src/lib/api/persons.ts`.»

Cursor открывает Vite + быстро пилит UI, добавляет тест Playwright, мерджит свой PR с handoff'ом обратно.

## Часто пропускают (грабли)

- `Принятые предположения` — нерефлексивный пункт. Часто упускают «я предположил, что Redis 1 экземпляр» или «я взял timeout 5 сек».
- `Известные риски` — особенно важно, если cloud LLM использован: «при rate-limit будет падать».
- `Рекомендованный агент` — без него Owner вынужден выбирать вслепую.
