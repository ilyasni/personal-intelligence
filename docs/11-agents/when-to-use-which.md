# Когда какого агента использовать

Шпаргалка для Owner-а: «у меня задача X — кого открывать».

## Быстрый выбор по типу задачи

| Тип задачи | Лучший выбор | Почему | Запасной |
|---|---|---|---|
| Спроектировать новый pipeline / сервис | **Claude Code** | сквозное планирование, читает много контекста | Cursor (если есть UI часть) |
| Написать ADR | **Claude Code** | хорошо обсуждает варианты | — |
| Большой рефакторинг через 10+ файлов | **Claude Code** | держит когерентность | Codex (если шаблонный) |
| Миграция Postgres (alembic) | **Codex** | автономен, шаблон стабильный | Claude Code (если меняется контракт) |
| Миграции Neo4j / Qdrant | **Codex** | то же | Claude Code |
| Генерация тестов на готовый сервис | **Codex** | масштабирует тесты | Claude Code (если нужны архитектурные кейсы) |
| Починить флакающий тест | **Codex** | хорошо находит источник на массивах прогонов | Claude Code |
| Обновить зависимости + поправить ломки | **Codex** | механически | Claude Code (если breakage сложный) |
| Новый компонент React / форма | **Cursor** | live preview, парная итерация | Claude Code (если связано с архитектурой UI) |
| UX-итерации (изменить layout, отступы) | **Cursor** | моментальный feedback | — |
| Поправить компонент по скриншоту | **Cursor** | DOM-inspection | — |
| Подключить новый MCP-tool в UI | **Cursor** | end-to-end в редакторе | Claude Code |
| Расследование «почему так» через 5+ файлов | **Claude Code** | держит контекст | Codex (если есть подсказка где искать) |
| Прочитать чужой PR и оставить комментарий | **Claude Code** | хорошее review | Codex |
| Накатать 30 PR'ов по шаблону | **Codex** | автономные runs | — |
| Написать новый ADR-черновик из дискуссии | **Claude Code** | синтез | — |
| Apply ADR — поправить код во многих местах | **Codex** | механика | Claude Code (если требует тонкого понимания) |
| Debug inicdent на проде | **Claude Code** | держит несколько источников | Cursor (если ошибка в UI) |
| Подготовить релиз — changelog, версии, тэги | **Codex** | механика | Claude Code |
| Документация — обновить страницу под фактическое поведение | любой | низкая сложность | — |

## По стадии задачи

```
[Исследование] → Claude Code (понять «почему так»)
       ↓
[Дизайн / ADR] → Claude Code (обсудить варианты, написать ADR)
       ↓
[Имплементация ядра] → Claude Code (если сквозное) или Codex (если изолированное)
       ↓
[Тесты массой] → Codex
       ↓
[UI-надстройка] → Cursor
       ↓
[QA / polish] → Cursor + Codex (e2e)
       ↓
[Релиз] → Codex
```

## По слою системы

Не делим жёстко по слоям, но в среднем:

- **Ingestion, processing pipelines, контракты событий** — Claude Code чаще (потому что сквозные).
- **Storage, миграции, retention jobs** — Codex чаще (потому что шаблонные).
- **MCP / REST endpoints — обвязка** — Cursor (потому что часто меняется и иницирует UI-доводку).
- **Admin UI** — Cursor.
- **Observability, CI** — Codex.

Это **тенденция**, а не закон. Любой агент может работать в любом слое, если открыт соответствующий тикет.

## По размеру изменения

- **< 100 строк, изолированное** — кто угодно. Чаще Cursor (если UI) или Codex (если backend).
- **100–500 строк, один сервис** — Claude Code или Codex.
- **500+ строк, несколько сервисов** — Claude Code (планирование) + Codex (массовая реализация).
- **Архитектурное** — Claude Code обязательно (как минимум для ADR).

## Когда нужны двое

Бывает полезно открыть два агента параллельно:

- Claude Code пишет архитектуру и обновляет docs, Codex параллельно генерирует тесты на новый контракт.
- Cursor дорабатывает UI, Codex параллельно прогоняет visual-regression на staging.
- Claude Code расследует баг, Codex параллельно собирает логи и метрики.

Координация — через handoff-блок в PR/таске + краткий апдейт в milestones.md.

## Когда не помогает агент

Если задача предполагает:

- общение с внешними людьми;
- стратегическое решение «делать или не делать»;
- юридические/этические вопросы;
- ручной тест с реальным Telegram-аккаунтом и наблюдением UX,

→ это work for human (Owner). Агент может подготовить материалы.
