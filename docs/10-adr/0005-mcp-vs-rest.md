# ADR 0005: MCP как первичный интерфейс, REST как дублирующий

- Дата: 2026-05-11
- Статус: Accepted

## Контекст

Внешним LLM (Claude, GPT, локальные) нужен интерфейс к памяти. У нас есть выбор:

## Варианты

**A. Только REST.**
+ Универсально, любая модель умеет HTTP.
+ Легко защищать API-key.
− Каждый клиент сам решает, как использовать (нет стандарта вызова tools).
− Менее «нативно» для современных агентских LLM.

**B. Только MCP.**
+ Стандартный протокол, поддерживается Claude Desktop / Claude Code / Cursor MCP-клиентом.
+ Из коробки tools, prompts, resources, sampling.
− Не все LLM пока умеют MCP (особенно при кастомных интеграциях).

**C. MCP + REST-фасад тех же tools.**
+ Лучшее из обоих миров.
+ Admin UI всё равно работает через REST.
+ Кастомные интеграции легко добавляются.
− Чуть больше кода (но фасад тонкий: тот же `libs/retrieval` под двумя слоями).

## Решение

**C — MCP первичный, REST дублирующий тот же набор инструментов.**

Внутри `services/mcp-rest-api`:
- `mcp/` модуль с tools и serializers.
- `rest/` модуль, который мапит те же tool-функции на REST-endpoints.
- Общий `libs/retrieval` ниже.

Авторизация унифицирована — API-key для обоих.

## Последствия

- (+) Внешние LLM подключаются нативно (Claude Desktop, Claude Code).
- (+) UI и custom-интеграции получают тот же контракт через REST.
- (−) Нужно поддерживать два контракта параллельно (но они автогенерируются из одних tool-определений).
- (−) Документация дублируется (см. `docs/04-api/mcp-api.md` и `rest-api.md`).
